# Capabilities and Benefits Framework

> How to describe value without vague comparative descriptors.

## The rule

Avoid comparative descriptors in product messaging.

Banned words (use sparingly):
- faster
- better
- easier
- seamless

Replace them with mechanisms, boundaries, and proof.

## The alternative: capability → benefit → proof

### Capability

Definition: a binary thing the product can do (or cannot do).

Template: “{{BRAND_NAME}} can {{VERB_PHRASE}}.”

### Benefit

Definition: the outcome for a specific audience anxiety.

Template: “So you can {{OUTCOME}} without {{PAIN}}.”

### Proof

Definition: an inspectable artifact that backs the capability.

Examples:
- docs section
- screenshot/recording
- PR/release note
- benchmark + methodology
